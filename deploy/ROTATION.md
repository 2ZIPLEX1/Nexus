# Ротация учётных данных — обязательно перед выкладкой на сервер

Этот чеклист нужно выполнить **руками**: сменить чужие пароли и ключи за вас
невозможно. Правки в коде закрыли будущие утечки, но уже утёкшие креды остаются
действительными, пока их не заменить.

## Почему это нужно, а не «на всякий случай»

Конкретные факты по этому проекту, а не общие рекомендации:

1. **Пароли SOCKS5-прокси лежали открытым текстом в `logs/bot.log`** — 155 строк
   (`src/account_manager.py` печатал полный URL с `user:pass`). Файл вычищен,
   но он больше двух лет копился и мог быть скопирован, отправлен в поддержку
   или синхронизирован.
2. **Проект лежит в папке OneDrive.** `.env`, `accounts.json`, `proxies.txt` и три
   `.maFile` синхронизированы в облако Microsoft. Формально они уже покинули
   машину и лежат в стороннем сервисе.
3. **`build_exe.py` зашивал `.env`, `accounts.json`, `proxies.txt` и cookies сессий
   в дистрибутив.** `--add-data` в PyInstaller не шифруется. Если вы кому-то
   отдавали собранный `.exe` — считайте всё содержимое скомпрометированным.
4. **Файл `sdsd`** (удалён) содержал пароль, ключи и прокси для `account3`
   отдельной копией, вне защиты `.gitignore`.
5. **API веб-панели держался на токене `professor`**, захардкоженном в исходнике.

Если хотя бы один пункт мог стать известен постороннему — ротация обязательна.

## Что менять

Отмечайте по мере выполнения.

### Steam (4 аккаунта: account1, account2, account3, account4)

- [ ] **Пароли** — сменить у всех четырёх. `accounts.json` хранит их открытым текстом.
- [ ] **Steam Web API key** — отозвать и выпустить заново:
      https://steamcommunity.com/dev/apikey (кнопка *Revoke My Steam Web API Key*).
- [ ] **Steam Guard: `shared_secret` / `identity_secret`** — есть у `account1` и
      `account2` (в `.maFile`). Это не «пароль», а **семя генератора кодов**:
      кто им владеет, тот проходит двухфакторку и подтверждает обмены без вас.
      Сменить можно только **сняв и заново привязав Steam Guard** к аккаунту —
      после этого старые `.maFile` становятся бесполезны.
      Учтите торговый холд после переустановки Guard.
- [ ] **Завершить активные сессии**: Steam → Настройки → Безопасность →
      *Выйти на всех устройствах*. В `.maFile` лежали живые `AccessToken` и
      `RefreshToken` со сроком до 2026 года.
- [ ] Удалить старые `.maFile` из корня проекта после переустановки Guard.

### CSGO.TM / market.csgo.com

- [ ] **API-ключи (4 шт.)** — перевыпустить в настройках профиля.
      Ключ передаётся в query-строке запроса (`src/csgotm_client.py`), то есть
      виден оператору любого прокси, через который шёл трафик.

### Прокси

- [ ] **Сменить пароль SOCKS5** у провайдера (в `proxies.txt` все 10 адресов
      используют одну пару логин/пароль — она была в логах).
- [ ] Обновить `proxies.txt` и поле `proxy.url` в `accounts.json`.

### Telegram

- [ ] **`TELEGRAM_BOT_TOKEN`** — перевыпустить через @BotFather (`/revoke`).
      До этого патча бот принимал команды **от кого угодно**, включая ввод
      Steam Guard кода.
- [ ] Задать `TELEGRAM_CHAT_ID` — без него входящие команды теперь отклоняются
      (fail-closed). При необходимости добавить `TELEGRAM_ALLOWED_USER_IDS`.

### Веб-панель

- [ ] Сгенерировать пароль: `python -m web.hashpw` → `WEB_API_PASSWORD_HASH`.
      Токен `professor` больше не работает, но если вы его где-то записывали —
      забудьте.

## После ротации

- [ ] Вынести проект **из папки OneDrive** (например, в `C:\bots\tm-steambot`),
      либо исключить каталог из синхронизации.
- [ ] Права на сервере:
      ```bash
      chmod 600 .env accounts.json proxies.txt *.maFile
      chmod 700 data logs
      chown -R botuser:botuser /opt/tm-steambot
      ```
- [ ] Проверить, что в логах чисто:
      ```bash
      grep -nE 'socks5?://[^*:]+:[^*@]+@' logs/bot.log   # должно быть пусто
      ```
- [ ] Убедиться, что `.env` и `accounts.json` не попали в git:
      ```bash
      git status --short          # секретов быть не должно
      git ls-files | grep -iE '\.env$|maFile|accounts\.json|proxies\.txt'
      ```

## Если репозиторий уже куда-то пушился

Сейчас каталог `.git` пуст, то есть истории нет и в удалённый репозиторий ничего
не уезжало. Но если копия проекта где-то публиковалась — удаления файла новым
коммитом **недостаточно**, содержимое остаётся в истории. Нужно переписать её
(`git filter-repo --invert-paths --path .env ...`), форсированно запушить и
всё равно ротировать ключи: считайте, что их уже скачали.
